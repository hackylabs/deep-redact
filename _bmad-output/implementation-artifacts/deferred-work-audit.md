## Deferred from: Epic 9 v3 capability parity restoration — Story 9.2 (2026-06-06)

- **[Addressed] `KeyRule` narrower than the v3 `BlacklistKeyConfig`** (`src/types/config.ts`, `src/core/validation/validate-config.ts`, `src/core/compiler/compile-redactor-plan.ts`, `src/core/runtime/redact-value.ts`) — Deep Redact v3's `BlacklistKeyConfig` let each blacklisted key carry its own `fuzzyKeyMatch`, `caseSensitiveKeyMatch`, `retainStructure`, `remove`, `replacement`, and `replaceStringByLength`, with `key: string | RegExp`. v4.0.0's `KeyRule` narrowed this to `{ key: string, fuzzyKeyMatch?, caseSensitiveKeyMatch? }`, moving per-key replacement/structure overrides onto `paths`/`PathRule` and dropping the per-rule object form for regex keys. Story 9.2 restores full parity: `KeyRule` gains `censor`, `remove`, `retainStructure`, and `replaceStringByLength`, and `key` widens to `string | RegExp`. Per-key overrides **reuse** the existing `CompiledRedactionPolicy` and `mergePolicy(defaults, overrides)` machinery already used by `PathRule` — no parallel per-key policy path is introduced. A key rule that specifies any override compiles a per-rule policy merged over the compiled global defaults (`compileKeyRulePolicy`); a key rule with no overrides leaves `policy` unset and keeps using the shared `exactKeyRules.policy` / `regexKeyRules.policy`, so existing output and the hot path are unchanged. Routing splits on `key instanceof RegExp`: a regex-keyed `KeyRule` is sent to `compileRegexKeyRules` (carrying its per-rule `policy`) instead of the literal path, and `CompiledRegexKeyRules.matchers` became `readonly CompiledRegexKeyRule[]` (`{ matcher, policy? }`) so regex keys reach the same parity as literal keys. At runtime the matched rule's per-rule policy is threaded through `DirectKeyMatchResult` / `resolveDirectKeyMatch`, and `selectActivePolicy` resolves `directKeyMatch.policy ?? plan.{exactKeyRules,regexKeyRules}.policy`; retain-structure descent at the key-rule policy site inherits the per-key policy unchanged, so descendants of a per-key `retainStructure` container are redacted under the inherited per-key censor. A per-key `censor`/`retainStructure` still passes through the Story 9.1 value-type allowlist at the shared leaf-replacement boundary — a per-key override does not bypass the `types` gate. Validation reuses the `PathRule` field validators (`validateCensorOption`, `validateBooleanOption`), accepts a regex `key`, rejects unsupported key-rule option names, and rejects `remove + censor` / `remove + retainStructure` at initialisation, mirroring the per-path invalid-combination rules (`applyRedaction` already evaluates `remove` before `censor` at runtime, but the init check still rejects the combination for parity). Precedence is unchanged: path rules outrank key rules, exact key rules outrank regex key rules, and first-match-wins holds among literal key rules. **Performance-neutral**: a compile-time merge plus at most one policy selection per key match, off the per-node hot path and outside the path-driven fast lane (which requires zero key rules and is therefore unaffected); no `test/bench/manifest.json` threshold changed and all six `maxOverheadPct` rows still pass on re-measurement. Pinned by the `v3 BlacklistKeyConfig parity: per-key overrides` contract suite in `test/contract/api/create-redactor.test.ts` (per-key string censor, function censor with context, `remove`, nested `retainStructure` with inherited per-key policy, `replaceStringByLength`, override-beats-global-default, regex key with overrides, no-override parity for string and regex, invalid-combination rejection, path-over-key and exact-over-regex precedence, first-match-wins, and the value-type-allowlist veto/permit coordination) and by the updated regex-matcher-shape assertions in `test/unit/core/compiler/compile-redactor-plan.test.ts`. The two v4.0.0 tests that pinned the narrowed key-rule surface (rejecting `remove` as an unsupported option and rejecting a regex `key`) were updated to assert the new contract while preserving their intent (rejecting a genuinely unsupported option name and a non-string/non-RegExp key). Evidence: `source .agents/initialise-env.sh && pnpm run test` (736 passed), `pnpm exec vitest run --config vitest.red-phase.config.ts` (89 passed), `pnpm exec tsc --noEmit` (clean), `pnpm lint` (exit 0), and `pnpm run bench && pnpm run verify:benchmarks` (all six rows passed, no threshold changed) on 2026-06-06.
