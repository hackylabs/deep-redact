## Deferred from: Epic 9 v3 capability parity restoration — Story 9.1 (2026-06-06)

- **[Addressed] Value-type allowlist (`types`) absent from the v4 surface** (`src/types/config.ts`, `src/core/compiler/compile-value-types.ts`, `src/core/replacement/apply-redaction.ts`, `src/core/runtime/redact-value.ts`, `src/core/runtime/navigate-exact-paths.ts`, `src/core/validation/validate-config.ts`) — Deep Redact v3 exposed a `types` option (default `['string']`) that gated whether a value was eligible for redaction; v4.0.0 dropped it, so `applyRedaction` redacted a matched value regardless of `typeof`. Story 9.1 restores `types?: readonly ValueTypeName[]` with strict v3 parity, defaulting to `['string']`. The option compiles once at initialisation into an immutable `typeof`-keyed O(1) boolean lookup (`compileValueTypes` / `CompiledValueTypesPlan`, mirroring `compileIgnoredValueTypes`) — no runtime array scan. The eligibility check (`isRedactableType`) is enforced at the single leaf-replacement boundary shared by both engines, so it is authoritative over every redaction source — exact-key, regex-key, exact-path, dynamic/wildcard-path, and whole-value substring rules — in both the generic traversal (`transformNode`) and the rule-driven engine (the three terminal apply helpers, with a vetoed *container* at a non-retain terminal routed to the general traversal so veto-and-descend output is byte-identical across engines). Veto semantics: a type-vetoed value is returned raw and routed as if unmatched — scalars (including transformable runtime values such as `Date`/`Map`/`BigInt`) pass through untouched, while a vetoed container is traversed so descendant rules and descendant transformables are still handled. Transformation stays serialise-gated (Story 8.3): a vetoed `Date` is transformed under `serialise: true` and returned raw (byte-identical to an unmatched `Date`) under `serialise: false`. `types` and `ignoredValueTypes` remain orthogonal. Initialisation rejects a `types` value that is not an array of supported type-name strings. **Performance-neutral**: the lookup runs only where a rule has already matched a value, off both engines' navigation hot loops; no `test/bench/manifest.json` threshold changed and all six `maxOverheadPct` rows still pass on re-measurement. Pinned by `test/unit/core/compiler/compile-value-types.test.ts` and the `Value-type allowlist (types) — Story 9.1` contract suite in `test/contract/api/create-redactor.test.ts` (ACs 1–7, plus the cross-engine parity and matched-but-vetoed≡unmatched invariants across `Date`/`Map`/`BigInt`). Existing v4 fixtures and tests that redacted a non-string value at a matched key/path were swept and adapted (incidental numeric placeholders converted to strings; container/non-string targets given an explicit widened `types` allowlist) so no assertion was relaxed. Evidence: `source .agents/initialise-env.sh && pnpm run test` (711 passed), `pnpm exec vitest run --config vitest.red-phase.config.ts` (89 passed), `pnpm lint` (exit 0), and `pnpm run verify:benchmarks` (all rows passed) on 2026-06-06.
